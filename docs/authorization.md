版1.0・2026-11-19。**権限は、この文書が正本。** 設計書やコードと食い違ったら、この文書を正とし、直すときはこの文書から直す。

## 1. 決まり

| # | 決まり |
|---|---|
| 1 | 判定は**サーバー側**でする。ボタンを隠すだけでは守りにならない |
| 2 | 事務所のものは、**必ず事務所から引く**（`/o/<office_id>/…` の `office_id` に自分が所属しているかを確かめ、その事務所の子として探す）。id だけで引かない |
| 3 | 他の事務所のもの・無いものは **404**（あることも教えない）。同じ事務所の中で役割が足りないときは **403** |
| 4 | 未ログインは、ログインの画面へ |
| 5 | **一覧にも同じ守り**を入れる（一覧は、自分が見てよいものだけを引く） |
| 6 | `office_id`・`role`・`member_role`・`status`・金額の計算結果は、画面から受け取らない |
| 7 | 運営は、事務所の画面を**見るだけ**。代わりに公開・合意・確定はしない。開いたら監査記録に残る |
| 8 | 下の表の「404」「403」のマス1つにつき、テストを1本書く。**守りを外すと、そのテストが落ちること**を確かめる |

## 2. 主体

公開の入口（段階0）：`GET /`、`GET /healthz`、`GET /static/<path:filename>` は未ログインを含む全員が利用できます。状態は変更しません。`/healthz` は DB に接続できる場合に `ok` だけを返し、接続情報や例外の詳細を表示しません。

| 記号 | 誰 |
|---|---|
| 未 | 未ログイン |
| 他 | 他の事務所の人（代表・職員） |
| 職 | その事務所の職員 |
| 代 | その事務所の代表 |
| つ外 | その困りごとに関わりのない、つなぎ手 |
| つ声 | その困りごとで、声をかけられた・伴走中の、つなぎ手 |
| 自 | 自治体の担当 |
| 運 | 運営 |

○＝できる。「→」＝ログインの画面へ。

段階3の入口は次の条件で利用できます。未ログインで各ホームを開くとログインへ移動します。

| 入口 | 条件 |
|---|---|
| `GET /login`・`POST /login` | 全員。認証結果を監査記録に残す |
| `POST /logout` | ログイン済み |
| `GET /account` | ログイン済み |
| `GET /o/<office_id>/` | 有効な事務所に所属する代表・職員と運営。運営の閲覧は記録。他は404 |
| `GET /t/` | ログインしたつなぎ手本人。他のロールは404 |
| `GET /r/<code>/` | 対象の市町村を担当する自治体ユーザー。未担当・存在しないコードは404、他のロールは403 |

## 3. 困りごと
段階4では、一覧は事務所ホーム、作成は `/needs/new`、閲覧は `/needs/<id>`、編集と型の手動選択は `/needs/<id>/edit`、公開・取り下げはそれぞれ `/publish`・`/withdraw` の POST です。いずれも `/o/<office_id>` の下に置きます。つなぎ手への限定表示は段階6の声かけからです。

| 操作 | 未 | 他 | 職 | 代 | つ外 | つ声 | 自 | 運 |
|---|---|---|---|---|---|---|---|---|
| 一覧を見る（その事務所の） | → | 404 | ○ | ○ | 404 | 404 | 404 | ○（記録） |
| 書く・下書きを直す | → | 404 | ○ | ○ | 404 | 404 | 404 | 403 |
| 見る（本文・翻訳・価値） | → | 404 | ○ | ○ | 404 | ○（型・曜日・条件。**本文は合意の後**） | 404 | ○（記録） |
| 公開・取り下げ | → | 404 | 403 | ○ | 404 | 404 | 404 | 403 |

## 4. 候補・声かけ・合意

| 操作 | 未 | 他 | 職 | 代 | つ外 | つ声 | 自 | 運 |
|---|---|---|---|---|---|---|---|---|
| 候補と理由を見る | → | 404 | ○ | ○ | 404 | 404（ほかの候補は見えない） | 404 | ○（記録） |
| 声をかける・取り消す | → | 404 | 403 | ○ | 404 | 404 | 404 | 403 |
| 受ける・断る | → | 404 | 404 | 404 | 404 | ○（自分への声かけだけ） | 404 | 403 |

## 6. つなぎ手の信用台帳
段階5の `GET /t/` はログイン中の本人の信用台帳を表示します。対象者の ID は受け取りません。運営の閲覧は運営画面の段階で実装します。

|---|---|---|---|---|---|---|
| 自分のホームを見る | → | 404 | ○ | 404 | 404 | ○ |

## 9. 確かめ方

1. 新しい入口（ルート）を足すときは、**先にこの表にマスを足す**。
2. `tests/app/test_authz_*.py` に、拒否のマスごとのテストを書く（他の事務所・職員・関わりのないつなぎ手・ほかの市町村）。
3. 守り（事務所から引く所・役割の確かめ）を1行外して、テストが落ちることを見る。戻す。
4. 段階15で、ルートの一覧（`flask routes`）とこの表を見比べ、表に無い入口が無いことを確かめる。
